# SMSI 归档备份客户端

SMSI Ubuntu 长期归档下载与验证客户端。Ubuntu 负责从 Google Drive 拉取归档、完成校验并发布本地副本，同时提供 Web 运维界面。

## 数据路径

```text
采集服务器 -> Google Drive -> Ubuntu 已验证副本
```

客户端不会调用 Google Drive 删除、移动或同步删除命令。来源文件缺失时，本地已验证副本保持不变。

## 验证门禁

- 新归档必须处于 `_smsi-archive-progress.json` 的 `verified` 终态；旧归档可使用已验证的 V3 manifest。
- 校验 manifest 协议、对象数、总行数和 Google Drive 完整读回证据。
- 每个对象校验大小与 SHA-256。
- 每个 Parquet 校验 schema 和行数；业务表额外重算内容摘要。
- schema 摘要和业务内容摘要由本机 pyarrow 重算得出，因此 pyarrow 固定在采集端的同一个大版本（`>=17,<18`）。万一这两个数字算不出来，而文件字节已经和 manifest 核对一致，客户端会报“无法复现采集端的摘要”并给出本机 pyarrow 版本，不会说副本损坏——字节相同的副本不可能损坏，对不上的只能是算法。行数来自 Parquet 自己的元数据，不受版本影响，仍按不一致报告。
- 下载先写入 `.partial`，整日通过后原子发布并写入 `.smsi-verified.json`。
- 已验证日期出现新的 manifest 时默认停止处理，不自动覆盖；唯一例外是带有严格维护证明的“移除旧运行报告”变更，客户端会重新验证现有业务文件、更新清单和凭据，不重新下载业务文件。

## 任务进度与取消

总览第一行是运行状态条：客户端是否在应答、自动同步开关、上次成功检查和下次检查时间，回答”这套东西还在干活吗”。下面第一张卡片是”需要处理”，没有问题时是绿色的 0，出现失败或清单变化时变红；磁盘占用常驻左侧，不在总览重复。当前任务只在两个地方出现：左侧”任务”入口带百分比，以及总览和任务页的任务条；这两页有完整任务条时，右下角的浮动传输窗不再重复显示。没有任务在运行时两页都只留状态一行，不显示空的进度槽和一排横线。

总览表显示远端 manifest 对象总量、本地已传输量和本地对象状态。点击“文件详情”才会读取一次远端 manifest 并对照本地正式目录、`.partial` 暂存目录，查看每个对象的待下载、传输中、已暂存或本地存在状态；页面刷新不会周期性重新列举网盘文件。

下载进度包含当前对象、活动并发、实时速度和预计剩余时间。设置中的带宽限制是整个任务的总上限，客户端会按实际并发分配给各个 rclone 工作进程。取消任务后日期状态变为“已取消”，已完成的临时对象保留在 `.partial`，正式目录不会发布，下次任务可以继续。

启动和定时任务采用增量检查：先读取远端日期清单，只处理新日期、未完成状态或本地验证凭据缺失的日期。完整验证过的历史日期不会因客户端重启而再次遍历所有对象。客户端只在最近 14 个归档日中低频抽查远端 manifest，每台服务器 7 天最多抽查 1 天；该抽查只读取清单和本地验证凭据，不读取业务对象。历史对象完整校验仅在用户点击单日“重新校验”时执行。

自动检查没有发现新归档、没有失败、没有取消，也没有清理陈旧状态时，只更新运行状态中的“上次检查/下次检查”时间，不写入任务历史。任务历史只保留实际下载、恢复校验、失败、取消、重启恢复和人工触发的操作，避免按检查周期产生大量空记录。

## Web 文件浏览与客户端更新

左侧统一使用“归档文件”入口，页面顶部在“云端 / 本地”之间切换。云端按采集服务器和日期读取 Google Drive 已发布 manifest；首次读取会把 manifest 的文件索引加载到当前页面，之后进入子目录或返回上级只在浏览器内存中切换，不重复访问网盘。本地直接浏览已验证目录和 `.partial` 暂存目录，即使网盘暂时不可用也能读取。两个列表只在进入页面、切换采集服务器或日期、手动重新读取时访问文件系统或网盘，不加入总览的周期刷新。

运行总览会在 manifest 包含 `runtime-report.json` 时读取小型健康摘要。当前分层报告分别显示归档日数据质量、运行过程记录和已恢复观察；只有数据质量会标记为归档日告警。未分层历史报告只显示为历史记录，不计入当前异常或跨服务器数据比较。旧报告经受控维护移除后显示“未生成”，业务归档、跨服务器业务数据比较和恢复验证仍保持有效。

双服务器对比沿用后台增量扫描自动刷新，只比较两侧均已完成本地恢复验证的日期。比较会核对采集器代码版本、Source Epoch、业务表和对象集合、对象元数据及 Schema；这些契约差异会显示为需要复核。两台独立采集产生的校验和、对象行数和对象大小差异保留为“正常差异”观察，不单独判定为故障。每个结果绑定两侧 Manifest SHA-256；Manifest 未变化时复用已有结果，不会在每轮扫描中重新打开全部历史报告。

Schema 对比会读取本地 Parquet 字段证据：字段缺失或类型改变仍需要复核；仅字段顺序变化，或 nullable 定义变化但两侧实际空值数均为零，显示为兼容观察，不改变数据健康状态。

“客户端更新”位于“设置”页面，只有三个按钮，状态只用一句话说明：现在是什么情况、下一步该点哪个。“检查更新”只读取 GitHub `main` 的提交信息，不下载任何文件。“更新版本”一次完成下载、校验、切换版本、重启客户端并自动刷新页面；页面依次显示下载阶段、字节进度、速度、预计剩余时间和重启等待秒数，不需要再点第二次，没有操作在进行时不显示空的进度条。“维护重启”是维护用的独立操作，只重启当前版本，即使已经下载了新版本也不会顺带安装。

更新或重启时若归档任务正在运行，客户端会先请求当前任务安全停止，将任务登记为待恢复并保留 `.partial` 中已完成的对象，再切换版本或重启；启动后任务会从已完成对象继续。更新助手拒绝或无法执行时，页面会直接显示助手返回的原因，同时恢复后台归档服务——只有连接中断才被当作“正在重启”。等待超过 90 秒仍未确认新版本启动时，页面会提示手动刷新核对版本，而不是停在一个无法判断的状态。

Ubuntu 更新助手只替换代码文件，不执行 `pip install`，因此会拒绝安装任何改动了 `requirements.txt` 的版本。页面会在下载后提前做同样的判断并直接说明：这一版需要在服务器上执行 `sudo bash deploy/install_ubuntu.sh`，此时“更新版本”按钮保持禁用，也不会为一次注定失败的切换而暂停归档任务。更新助手仍会执行最终忙碌检查，只接受固定版本号和固定运行目录，不能执行任意命令。首次安装或更新助手变更时，同样需要重新运行 `deploy/install_ubuntu.sh`。

安装脚本会在装好依赖后显式重启更新助手和客户端本体，并打印已安装的版本号，因此脚本执行完毕新版本就已经在运行，不需要再手工重启。重启时若正在下载归档，客户端会先取消当天任务并保留 `.partial` 中已完成的对象，下一轮检查自动继续。

## 告警通知

告警通知在“设置”页面开启，需要 Telegram 机器人令牌和会话 ID。客户端在 Ubuntu 上无人值守运行，它发现却送不出去的问题等于没有发现，所以这里有两个彼此独立的触发条件：一是客户端已记录的事件，按设定的最低级别（警告及以上，或仅错误）转发，每条只推送一次；二是长时间没有成功完成归档检查——客户端一旦停止工作就不再产生任何事件，只有时间能发现这种故障，默认阈值 6 小时，恢复后会再补一条恢复消息。首次开启只记录起点，不会把历史事件倒灌进会话。

告警不在数据路径上：发送失败会在下一轮检查时自动重试，不会让同步、下载或校验失败。检查按计划反复执行，同一个故障会被反复记录，因此同一条失败在一小时内只推送一次，其间的重复次数会附在下一条消息里（“期间重复 12 次”）；同一条消息来自不同采集源算作不同故障，而同一个故障发生在几十个归档日只算一个。同一个失败原因只在事件日志记录一次，最近一次失败原因显示在“设置”页面的告警状态行，因为通道本身坏掉时无法用它通知自己。消息使用纯文本并在超长时截断，避免格式解析导致整条消息被拒收。机器人令牌只保存在状态目录，接口只回显末四位，保存其他设置时留空即保持不变。“发送测试消息”只验证通道当前是否可用，不推进告警游标，也不影响待推送内容。

## Ubuntu

```bash
sudo apt install python3 python3-venv rclone
sudo bash deploy/install_ubuntu.sh
```

默认安装目录为 `/data/smsi-archive-client`，状态目录为 `/data/smsi-archive-client-state`，归档目录为 `/data/smsi-archive`。Web 服务监听 `0.0.0.0:8788`，应在防火墙中只允许可信局域网访问。

把安装目录本身保持为本仓库的 checkout，改动了 Python 依赖的版本就可以这样升级（安装脚本发现源目录等于安装目录时不再复制文件，直接就地安装）：

```bash
cd /data/smsi-archive-client && sudo git pull && sudo bash deploy/install_ubuntu.sh
```

初次配置 Google Drive：

```bash
sudo systemctl stop smsi-archive-client
sudo -u smsi-archive rclone --config /data/smsi-archive-client-state/rclone.conf config
sudo chmod 600 /data/smsi-archive-client-state/rclone.conf
sudo systemctl start smsi-archive-client
```

服务状态与日志：

```bash
systemctl status smsi-archive-client
journalctl -u smsi-archive-client -n 100 --no-pager
```
